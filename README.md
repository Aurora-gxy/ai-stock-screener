# 自然语言智能选股与策略解释器

> 同花顺 26/27 届 AI 题 · 题目 02

把「经营改善、估值合理、走势相对稳定」这样的模糊选股意图，转成**用户可检查、可修改、可执行**的数据条件，在扶摇真实数据上筛选，并解释每只股票**为何入选、为何被排除、条件变化会带来什么影响**。

- 在线体验：https://ai-stock-screener-xinyi.streamlit.app （长时间无人访问会休眠，打开后点击唤醒按钮，约 30 秒）
- 代码仓库：https://github.com/Aurora-gxy/ai-stock-screener

---

## 1. 产品选择：做什么、不做什么

| 做 | 不做 |
|---|---|
| 把模糊意图翻译成透明的数据条件，并让用户确认和修改 | 不预测涨跌、不给目标价、不给买卖建议、不承诺收益 |
| 逐股、逐条件给出「通过 / 未通过 / 无法判断」及原始字段、时点、口径 | 不把缺失或过期的数据当作「正常」，不静默补值 |
| 告诉用户「哪个条件筛掉最多」「放宽或收紧一档会怎样」 | 不做黑箱打分排名 |
| 支持比较、保存、历史回看、转为监控任务 | 不做实盘交易或下单 |

目标用户：有选股想法、但说不清具体指标阈值的个人投资者。核心价值是**把「AI 理解」和「数据判定」拆开**，让用户看得见、改得了每一步。

## 2. 主链路

```
自然语言意图
  │
  ├─ 合规检查（确定性规则）：预测 / 收益承诺 / 买卖建议 / 内幕 / 隐私 → 明确拒绝该部分
  ├─ AI 解析（DeepSeek）──┐
  ├─ 规则解析（词表+正则）─┴─ 交叉核对，差异展示给用户
  ▼
澄清模糊词（每个模糊词有 2～3 种可执行口径，默认值已预填）
  ▼
条件编辑表（可增删改、启停；所有指标来自白名单）
  ▼
冲突识别：冲突（不可能同时满足，阻止执行）/ 张力（可能结果很少）/ 提示（口径注意）
  ▼
确定性筛选引擎（扶摇数据）→ 入选 / 排除 / 无法判断
  ▼
解释：逐股原因 + 原始字段 + 时点；逐层漏斗；单条件放宽 / 收紧 / 删除的影响；（可选）AI 文字摘要 + 数字回查
  ▼
比较 / 历史回看 / 保存方案（可导出导入）/ 转为监控任务（与上次结果对比新进入、移出）
```

## 3. AI、筛选引擎、数据工具的职责边界

| 层 | 模块 | 负责 | 不负责 |
|---|---|---|---|
| **AI 层** | `core/intent.py` `core/llm.py` `core/explain.py` | 理解自然语言 → 输出条件 JSON；识别模糊词与不支持的诉求；把引擎结果写成文字摘要 | **不接触任何行情 / 财务数字**，不做筛选判定，不能发明指标 |
| **校验层** | `intent.validate_condition` `explain.verify_numbers` `compliance.py` | LLM 输出必须过白名单 + 数值校验；摘要中的每个数字必须能在引擎结果中找到；违规表述被移除 | — |
| **确定性筛选引擎** | `core/engine.py` `core/conflicts.py` | 逐股逐条件比较、汇总结论、漏斗、敏感性分析、冲突识别 | 不调用 LLM，同输入必同输出 |
| **数据工具层** | `core/fuyao.py` `core/features.py` | 调用扶摇 API、重试与限流、记录 request_id、把原始字段计算成指标并标注来源 / 时点 / 口径 / 状态 | 不做判断，失败就显式报错 |

LLM 不可用（未配置、超时、输出不合法）时，自动退回规则解析，页面会明确提示。

## 4. 数据来源与口径

全部数据来自 **扶摇金融数据 API**（`https://fuyao.aicubes.cn`，请求头 `X-api-key`）。

| 用途 | 接口 |
|---|---|
| 股票池成分股 | `/api/a-share-index/constituents/ths-stock-list` |
| 最新价、涨跌幅 | `/api/a-share/prices/snapshot` |
| 日 K 线（前复权） | `/api/a-share/prices/historical` |
| 基准指数 K 线 | `/api/a-share-index/prices/historical` |
| 利润表、资产负债表、现金流量表 | `/api/a-share/financials/*` |

指标口径（页面「每个指标的数据来源与统计口径」也可查看）：

| 指标 | 口径 |
|---|---|
| 营收 / 归母净利同比 | 最新报告期 vs 上年同一报告期；上年同期 ≤0 视为无意义 |
| 经营现金流 | 最新报告期经营活动现金流净额 |
| ROE（近似） | 最近年报归母净利 / 同年末所有者权益（含少数股东权益，偏保守） |
| 资产负债率 | 最新报告期负债合计 / 资产总计 |
| PE（静态） | 最新价 / 最近年报基本 EPS；EPS ≤0 视为无意义并判为不满足 |
| PE 分位 | 当前股票池内 PE>0 股票中的相对位置 |
| PB（估算） | 用「归母净利 / EPS」反推总股本，再算每股净资产 |
| 波动率 / 回撤 / 涨跌幅 / 均线偏离 / 成交额 | 由前复权日 K 线计算，窗口见指标名 |

**为什么 PE 是自己算的**：扶摇文档中没有直接的估值（PE/PB/市值）接口，所以用价格与财报字段计算，并在页面明确标注「静态」「估算」。

**数据状态**：每个指标都有状态 `ok / na（无意义）/ missing（缺失或接口失败）/ stale（财报超过 200 天或 K 线超过 10 天未更新）`。`missing` 和 `stale` 的股票归入「无法判断」，**不会被当作通过**。

## 5. 启动方式

```bash
git clone <仓库地址> && cd <仓库目录>
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # 填写 FUYAO_API_KEY 与 DEEPSEEK_API_KEY
python scripts/probe_api.py # 先核对扶摇接口字段（可选但推荐）
streamlit run streamlit_app.py
```

运行测试（不需要网络和 Key）：

```bash
pytest -q
```

### 环境变量

| 变量 | 必填 | 说明 |
|---|---|---|
| `FUYAO_API_KEY` | 是 | 扶摇 API Key，未配置时页面禁止执行筛选，不会用假数据代替 |
| `DEEPSEEK_API_KEY` | 否 | 未配置时使用规则解析；AI 摘要不可用 |
| `DEEPSEEK_BASE_URL` / `DEEPSEEK_MODEL` | 否 | 默认 `https://api.deepseek.com` / `deepseek-chat` |

### 部署（Streamlit Community Cloud）

1. 把仓库推到 GitHub（确认 `.env` 没有被提交）
2. share.streamlit.io → New app → 选择仓库，Main file 填 `streamlit_app.py`
3. Advanced settings → Secrets 粘贴 `.streamlit/secrets.toml.example` 的内容并填真实 Key
4. Deploy

## 7. 已知边界与未做事项

- **估值为自行计算**：静态 PE 与估算 PB，不是 TTM，也不是官方口径
- **ROE 为近似值**：分母含少数股东权益
- **同比基于「各自最新报告期」**：不同公司可能处于不同报告期，页面逐股展示时点
- **历史回看不是严格回测**：用今天的数据选股再看过去，存在前视偏差和幸存者偏差；未计交易成本
- **监控任务为手动触发**：未部署后台定时器；云端重启会清空本地保存，请用导出功能备份
- **股票池限于 5 个标准指数**：沪深 300、中证 500 首次加载需要数分钟（每只股票 5 次接口调用），当天之后走缓存
- **未接入**：行业板块筛选、资金流、分红、市值、新闻舆情、iFinD MCP。这些诉求会在页面上被标为「无法执行」，不会被静默忽略
- **未做**：用户账户体系、多用户隔离、行业内估值分位、财报 TTM 计算

## 8. 合规声明

本产品仅根据公开数据和用户设定的条件做客观筛选与解释，不构成投资建议，不预测股价涨跌，不承诺收益。仓库不包含任何 API Key 或用户隐私数据；测试使用的全部为构造数据。
